## 6. Does `resume` detect a harness change at the same version?

`resume` compares the recorded `executor.harness` (installed version, plus the commit from pip's `direct_url.json`)
with the installed one.
- **Detected:** a different version, or a different commit installed from git (the pinned path).
- **Not detected (the gap):** with the same version number, a change of code installed without VCS metadata (a
  wheel, sdist, local path or editable install) gives `commit: null` on both sides. So does a site-packages file
  edited in place.

Narrow fix proposal, not implemented:
- Add `record_digest` to the identity: the SHA-256 of the distribution's `RECORD`, which lists a hash for every
  installed file.
- In `resume`, compare only the keys present in the recorded identity, so runs recorded before the change still
  resume.
- Effect on `compare`/`pool`: they treat a changed executor identity as "executor changed". Runs recorded before and
  after the change would then show as not comparable unless the new key is ignored there too.
