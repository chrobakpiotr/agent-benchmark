## 6. Does `resume` detect a harness change at the same version? (fixed 2026-10-19)

Fix commit: `a93521e`. Accepted by Master as closing the requested fix, based on this report, not an independent code
review.

**The gap:** `resume` compared `executor.harness` = {version, commit from pip's `direct_url.json`}. An installation
without VCS metadata has `commit: null`. A changed installed file with the same version therefore resumed
undetected.

**The fix** (approved by Master; `src/agent_benchmark/harness_port.py`, `runner._check_harness_unchanged`):
- **Recorded identity:** every run now records `fingerprint: {method: "record-listed-files-content-sha256/v1",
  digest}` next to the version and commit.
- **What the digest covers:** the actual content of every file the distribution's RECORD lists, keyed by relative
  path. RECORD's own hashes are not trusted, and RECORD is parsed directly because `importlib`'s `files` silently
  drops missing files.
- **Excluded from the digest:** compiled caches, files outside the install root (scripts carry the interpreter path)
  and install-specific dist-info files (`RECORD`, `INSTALLER`, `REQUESTED`, `direct_url.json`).
- **When `resume` refuses:**
  - any difference in version, commit or fingerprint;
  - a missing or unreadable file, or a missing RECORD (fingerprint `null`);
  - a run recorded before the fix without a commit, because an unchanged installation cannot be shown for it.
- **Old runs:** a run recorded before the fix that has a commit resumes only on an equal version and commit. Nothing
  is written back into old runs; they stay readable and can be regraded.
- **Tests:** `tests/test_agent_cli_run.py`:
  - `test_fingerprint_reads_file_content_not_record_hashes`: same RECORD, edited file → new digest; caches and
    installer details don't count; a missing file → `null`;
  - `test_harness_identity_is_recorded_reported_and_resume_refuses_a_changed_harness`;
  - `test_resume_of_a_run_recorded_before_fingerprints`.
- **End to end:** harness v0.12.0 installed from a source directory without VCS metadata (`commit: null`). A fake-CLI
  run stopped after its first trial; then one line was appended to the installed `agent_harness/contract.py` with
  RECORD unchanged.
  - With the edited file, `resume` refused ("agent-harness changed since the run started").
  - With the file restored, `resume` proceeded.
- **Note:** the same commit installed from git and from a plain directory yields different fingerprints (their
  RECORD-listed files differ). Resuming across install methods is therefore refused, which is the conservative
  outcome.
- **Effect on `compare` and `pool`:** they treat a changed executor identity as "executor changed". Runs recorded
  before the fix (no fingerprint) and after it are therefore not grouped together.
